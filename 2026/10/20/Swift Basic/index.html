Swift Basics

本笔记整理自 Swift 官方语言指南的 The Basics 章节。
参考：The Swift Programming Language — The Basics

1. Swift 基础特点

Swift 提供常见的基础类型，例如 Int、Double、Bool 和 String，也提供数组、集合、字典、元组和可选类型等数据结构。

Swift 是**类型安全（type-safe）**的语言：如果某段代码需要 String，编译器会阻止你误传 Int。Swift 会尽可能在编译时发现类型不匹配，数值类型之间也不会自动隐式转换，通常需要明确转换。

Swift 也强调内存安全（memory safety）：代码只能以受语言规则约束的方式访问有效数据。大多数安全检查由编译器完成，某些检查则在运行时进行。Swift 仍提供 unsafe 等接口，但使用它们时，安全责任更多地由程序员承担。

2. 常量与变量（Constants and Variables）

常量和变量用于给值命名：

  • let 声明常量，赋值后不能再改变。
  • var 声明变量，之后可以重新赋值。

常量可以先声明、之后再赋值，但必须保证在读取前被赋值，而且不能重复赋值。

多个变量的声明

同一行声明的变量可以有不同类型，但每个变量都要满足自身类型规则。

3. 整数（Integers）

整数是没有小数部分的数，例如 42、-23 和 0。Swift 提供有符号和无符号整数，并支持不同位宽，例如 Int8、UInt8、Int32。

一般用途优先使用 Int。它的位宽与当前平台的原生字长相同。只有在外部数据格式、内存需求或明确的数值范围要求下，才通常需要选择 Int8、UInt32 等固定宽度类型。

4. 浮点数（Floating-Point Numbers）

浮点数可以表示带有小数部分的数，例如 3.14159 和 -273.15。

常见类型：

  • Float：通常为 32 位。
  • Double：通常为 64 位，常规浮点运算一般优先使用它。

浮点数能够表示非常大、非常小的数，但不能精确表示范围内的所有数值。运算结果通常会舍入到最接近的可表示值，因此不要默认用 == 比较两个经过计算的浮点数。

需要精确金额或固定小数位的场景，可以考虑以整数最小单位存储，或使用符合业务舍入规则的专用数值类型。

7. 可选类型（Optionals）

可选类型表示一个值可能存在，也可能不存在。它的类型写作 Type?：

非可选的 String 必须始终有一个字符串值；String? 则可以没有值。

访问可选值之前需要安全地处理 nil，常见方式包括 if let、guard let、可选链和 ??。不应在没有充分保证时使用强制解包 !。

Int(input) 可能失败，因此返回可选的 Int?，而不是假设输入一定有效。

8. 错误处理（Error Handling）

可恢复或预期中的失败通常使用错误处理表达。函数可以通过 throws 声明自己可能抛出错误；调用时使用 try。

可以根据不同错误类型分别处理：

  • throws：声明函数可能抛出错误。
  • try：标记可能抛错的调用。
  • do：建立错误处理作用域。
  • catch：捕获并处理匹配的错误。

错误可以继续向调用者传播。错误处理适用于可预期、可恢复或需要说明原因的失败；断言和前置条件用于程序逻辑必须成立的假设，不能替代错误处理。

9. 断言与前置条件（Assertions and Preconditions）

断言与前置条件用于表达程序运行时必须满足的条件。条件为假时，程序会停止执行；它们不是用于处理普通、可恢复错误的机制。

断言（Assertion）

assert 常用于开发阶段检查假设，帮助尽早发现程序逻辑错误。

如果条件失败，程序终止。断言也可以用来记录代码中的预期条件。

与断言相比，前置条件更适合表达在发布版本中也必须成立的条件。不过，使用 -Ounchecked 编译时，前置条件检查可能被省略；不应把它当作处理不可信输入的唯一防线。

选择哪一种？

  • 可预期、可恢复的失败：使用返回值、可选类型或 throws。
  • 开发阶段的逻辑假设：使用 assert。
  • 继续执行必须成立的条件：使用 precondition。
  • 开发阶段尚未实现的代码占位：可使用 fatalError，但应在交付前完成实现。

precondition(index > 0, ...) 只适用于索引必须大于 0 的特定设计。普通数组下标通常从 0 开始，应按实际有效范围检查。
