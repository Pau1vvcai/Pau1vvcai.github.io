Edhita 项目学习

Edhita 项目学习

仓库：tnantoka/edhita

Edhita 是一个使用 SwiftUI 编写的 iOS 文本编辑器。本笔记通过阅读项目代码，梳理应用启动、文件浏览、文本编辑、预览、设置保存及 SwiftUI 与 UIKit 的协作方式。

一、应用核心流程

二、代码职责概览

职责 主要文件 作用
启动与应用外壳 EdhitaApp.swift、AppDelegate.swift 创建根界面；处理首次启动初始化
数据与业务逻辑 FinderItem.swift、FinderList.swift、Settings.swift 管理文件条目、读写文件和保存偏好
SwiftUI 界面与系统桥接 Views/ 下的视图文件 展示文件列表、编辑器、设置、预览和分享界面

三、应用启动与首次运行

应用入口是 @main struct EdhitaApp: App。它创建应用的根界面，并根据设备类型选择相应的导航布局。@UIApplicationDelegateAdaptor(AppDelegate.self) 则让 SwiftUI 应用接入 UIKit 的 AppDelegate 生命周期。

首次启动时，AppDelegate 检查 Settings.shared.firstLaunch。如果这是首次运行，就调用 FinderList.createExamples() 创建示例目录和文件，然后更新首次启动标记。

这展示了 SwiftUI 应用与 UIKit 生命周期代码协作的一种方式。

四、文件浏览

FinderList：管理目录内容

FinderList 保存某个目录的 URL 和该目录下的 [FinderItem]。它使用 FileManager 读取目录内容，并按修改时间排序。

@Published 标记的属性发生变化时，会向观察者发出变更通知。FinderListView 使用 @ObservedObject 观察 FinderList，因此列表可以随 items 更新。

文件列表与导航

FinderListView 使用 List 和 ForEach 显示文件条目。它根据 item.isDirectory 决定导航目标：

  • 文件夹：进入新的 FinderListView。
  • 文件：打开 EditorView。

行内容由 FinderItemView 绘制，例如显示文件或文件夹图标、文件名和修改时间。

五、文件条目：FinderItem

FinderItem 表示一个文件或文件夹：

  • Identifiable 要求提供 id，供列表等界面稳定识别条目。
  • Hashable 让条目可用于需要哈希能力的场景，例如以 \.self 作为 ForEach 的标识。
  • id 和 filename 是计算属性：每次访问时根据 url 计算。
  • url.path 是完整路径；url.lastPathComponent 是路径中的最后一部分，通常是文件名。

可选值与文件读取

项目中的文件读取逻辑可以用以下模式概括：

  • String? 表示字符串可能不存在。
  • try? 把抛出的错误转换成 nil。
  • ?? "" 在读取失败或没有内容时提供空字符串作为默认值。

这种写法简单，但会隐藏错误原因。若需要向用户显示“权限不足”或“文件已损坏”等具体信息，应保留并处理原始错误。

六、编辑器的数据流

编辑器使用 @State 保存当前正在编辑的文本，并把绑定传给 TextEditor：

数据流可以理解为：

  • @State：表示 EditorView 拥有并维护 content。
  • content：状态的当前值。
  • $content：Binding<String>，允许 TextEditor 读取和修改该状态。
  • onChange：监听状态变化并执行副作用，例如写文件或刷新预览。

@State 只负责界面状态管理，并不会自动把内容保存到磁盘。文件写入是由 item.update(content:) 显式完成的。

编辑器的预览、编辑和分屏模式由 Mode 枚举表示。CaseIterable 可以用于遍历所有枚举值，Identifiable 则方便在 SwiftUI 控件中识别各个选项。

七、SwiftUI 状态包装器

写法 状态归属 常见用途
@State 当前 SwiftUI 视图 局部界面状态，如编辑文本或弹窗开关
@Binding 由父视图或其他对象拥有 子视图需要读写父视图状态
@Published ObservableObject 模型对象 发布模型属性的变化
@ObservedObject 不拥有对象的视图 观察外部传入的 ObservableObject
@StateObject 当前视图拥有的 ObservableObject 在视图生命周期内创建并持有模型

父视图可以把自己的状态以绑定形式传给子视图：

子视图修改 name 时，实际更新的是父视图拥有的状态。

读 SwiftUI 属性时可以先问两个问题：

  1. 谁拥有状态？ 是视图、模型，还是上层对象？
  2. 谁需要读写状态？ 子视图是否需要通过绑定共享修改？

八、SwiftUI 与 UIKit 桥接

SwiftUI 用声明式方式描述界面，UIKit 和 WebKit 则提供许多现成的视图与控制器。通过 Representable 协议，可以将 UIKit 组件放入 SwiftUI 界面树中。

  • UIViewRepresentable：包装 UIKit 的 UIView，例如 WKWebView。
  • UIViewControllerRepresentable：包装 UIKit 的 UIViewController，例如系统分享面板。

使用 UIViewRepresentable 包装 WKWebView

  • Markdown 文件：读取文本 → 使用 Ink 转为 HTML → 调用 loadHTMLString。
  • 其他 URL：创建 URLRequest → 调用 load。

从 SwiftUI 访问 UIKit 控件

项目使用 SwiftUI-Introspect 获取 TextEditor 底层的 UITextView，以调用键盘辅助栏、光标移动、撤销和重做等 UIKit 功能。

这提高了与 UIKit 的互操作性，但也会依赖 SwiftUI 控件的底层实现。系统或依赖库升级时需要留意兼容性。

Context 的作用

makeUIView 和 updateUIView 中的 context 提供桥接所需的上下文信息，例如协调器（Coordinator）。当 UIKit 事件需要回传给 SwiftUI 时，协调器可以负责连接两边。

九、Markdown 与网页预览

PreviewWebView.swift 使用 UIViewRepresentable 将 WKWebView 嵌入 SwiftUI：

  • Markdown 文件通过 Ink 转换为 HTML，再交给 WebKit 显示。
  • 其他文件或 URL 则使用 URLRequest 加载。

PreviewWebView 接收了 reloader 属性。笔记中的代码显示 updateUIView 尚未使用它；如果这个值的目标是控制预览刷新，就需要检查更新逻辑是否根据它重新加载内容。

十、设置与持久化

单例：Settings.shared

static let shared 提供一个共享实例；private init() 阻止其他代码随意创建新的 Settings 实例。

使用 UserDefaults

Settings 将字体、字号、颜色和键盘工具栏开关等轻量设置保存到 UserDefaults：

UserDefaults 适合保存偏好设置，不适合保存整份文档正文。Edhita 将文档保存为文件，将轻量设置保存在 UserDefaults。

单例与持久化是两个不同概念：

  • 单例：提供同一个对象的共享访问方式。
  • 持久化：让数据在应用重启后仍然存在。

项目中的 Settings 没有遵循 ObservableObject，设置属性也没有通过 @Published 发布变化，因此设置变化不会自动通知所有已显示的 SwiftUI 视图。

十一、闭包与异步回调

广告初始化流程展示了闭包、@escaping 和弱引用捕获的用法。

@escaping

函数参数闭包默认不能在函数返回后继续使用。若闭包会被保存起来或交给异步操作，必须标记为 @escaping：

广告初始化是异步的：start 发起工作后先返回，SDK 准备完成后才调用回调。

[weak self]

[weak self] 避免异步闭包因为强引用 self 而延长对象生命周期，尤其是在对象与闭包之间可能形成引用环时。

弱引用可能变成 nil，所以使用 self?.property 进行安全访问。

回调行为需要明确

阅读异步代码时，除了看闭包何时执行，还要确认：

  • 成功、失败和取消时是否都会调用回调？
  • 回调会不会被调用多次？
  • 是否需要保证只执行一次？
  • 若持有闭包的对象已经释放，后续行为是什么？

如果错误路径直接 return，但没有报告失败，调用方可能一直等待。若多个异步分支都能调用回调，还需要避免重复执行。

十二、外部依赖

项目通过 Swift Package Manager 引入的主要依赖包括：

  • Ink：将 Markdown 转为 HTML。
  • SwiftUI-Introspect：从 SwiftUI 视图访问底层 UIKit 控件。
  • Google Mobile Ads：展示广告，并处理相关授权流程。

十三、文件操作代码阅读

读取目录并排序

  • static 表示该方法属于 FinderList 类型本身，可通过 FinderList.items(for:) 调用。
  • contentsOfDirectory 可能抛错；try? 会把错误转成 nil。
  • guard let 在读取失败时进入 else。
  • map 将 [URL] 转为 [FinderItem]。
  • sorted 按修改时间从新到旧排列。
  • $0 和 $1 是闭包中前两个参数的简写。

可改进点： fatalError() 会直接终止应用。目录读取失败通常更适合通过 throws、错误状态或空状态反馈给界面。

删除条目

  • guard let：条目不存在时提前退出。
  • firstIndex(of:)：查找条目在数组中的位置，返回可选下标。
  • if let：只有找到下标才从数组移除。
  • item.destroy()：删除磁盘上的文件或目录。

注意： 如果条目不在当前 items 数组中，代码仍会执行 item.destroy()。这可能是设计意图，也可能需要根据业务规则调整。

创建文件或文件夹

  • self.url 是当前目录的 URL。
  • appendingPathComponent(name) 构造新条目的 URL。
  • isDirectory 决定创建文件夹还是空文件。
  • try? 会忽略创建失败的错误。
  • refresh() 重新读取目录内容。

可改进点： 如果创建失败，列表仍会刷新，但用户不会知道失败原因。实际产品通常需要展示或记录错误。

下载并写入数据

  • URL(string:) 可能无法生成 URL，因此使用 guard let 检查。
  • Data(contentsOf:) 读取数据，成功后写入当前目录。
  • refresh() 更新列表。

这个示例中的 Data(contentsOf:) 是直接读取数据的简化方式。真正的网络下载通常应使用异步网络 API，并处理请求失败、状态码和用户取消等情况。

十四、项目中的主要 Swift 难点

  1. SwiftUI 状态流：理解 @State、@Binding、@Published、@ObservedObject 和 @StateObject 各自对应的状态归属。
  2. SwiftUI 与 UIKit 桥接：区分 makeUIView 和 updateUIView 的职责。
  3. 可选值与错误处理：理解 try?、guard let 和 if let，同时留意错误是否被隐藏。
  4. 异步闭包生命周期：理解 @escaping、[weak self] 和回调调用次数。
  5. 单例与持久化：区分共享对象与跨重启存储。
  6. 文件系统错误：理解读写权限、路径有效性和文件操作失败的处理方式。

总结

Edhita 展示了 SwiftUI 应用如何把界面状态、文件读写、UIKit 桥接和异步 SDK 组合起来；读懂它的关键是追踪“状态归谁、变化如何传播、失败如何处理”。
